启动恢复器 代码结构（当前结构）。

最后更新：北京时间 2026/11/22日 19:45分

源码根：src\WorkspaceRestorer（本地外层项目里是 yuanwenjian\src\WorkspaceRestorer）
入口：Shared\UI\Shell\App.cs
总控制器：Shared\UI\Shell\ApplicationController\ApplicationController.cs（同名文件夹内十五份分部），另有 StartupRestore\Core 和 Applications\Restore 两个分部
主窗口：Shared\UI\Shell\MainWindow\MainWindow.cs（同名文件夹内七份分部），各工作区页面是它的分部类
图标位置保存页面：DesktopLayout\UI\Pages\DesktopLayoutPage\（同名文件夹内六份分部）
测试程序：tests\TestRunner\TestRunner.cs，十八份分部，由 Test.ps1 调用；用例数量以 Test.ps1 输出为准

三个工作区与公共回收站：

1. StartupRestore
   启动与恢复。Core 负责捕获、恢复、保存编排；Browsers 放浏览器采集、恢复与跳转；UI 放页面；Windows 负责窗口可见性、恢复前体检与恢复后巡检；SessionCaptureService 是通用会话采集服务；Deletion 负责小项连带删除规则；Settings 放本工作区设置。

2. Applications
   自启动应用。Core 负责桌面扫描和方案模型；UI 是页面；Restore 负责恢复转接与自动启动；Browsers 放浏览器方案与父/子项；Deletion 负责小项删除适配；Settings 放本工作区设置。

3. DesktopLayout
   图标位置保存。Core 负责桌面扫描、布局文件和图标坐标；UI 放页面和编辑器；Settings 放本工作区设置。

4. Shared\UI\RecycleBin
   回收站页面，三个工作区共用一份；回收站本身也是公共页面。

公共层：

1. Shared\Core
   公共时间格式（TimeText）；Cards 放卡片的数据与算法（方案文件夹树、拖动几何/落点）。
   镜像的纯命名和相对路径在 Cards\PlanFolders\Mirror，只做计算、不碰磁盘。

2. Shared\UI
   公共控件、主题与字体（AppFonts）、颜色令牌与即时主题（Theme\Tokens、ThemeResourceKeys、ThemeService）、
   悬浮提示（Theme\ToolTips）、卡片界面与交互（Cards）、设置页、外壳。
   界面多语言在 Text\Localization；恢复完成文案在 Text\Restore。

3. Shared\Core\Localization
   语言代码与语言元数据模型（LanguageDefinition / LanguageTags），不依赖 WPF；
   资源发现和查表在 Shared\UI\Text\Localization，页面不写死语言枚举。

3. Shared\Infrastructure
   JSON 原子写入、日志、剪贴板、路径规范化（PathText）等底层设施；方案镜像的磁盘引擎和两个公开壳在 PlanMirrors。
   PathText 只做 Windows 路径字符串整理：不读写文件、不引用 UI/业务，保留 C:\ 与 UNC 根。

4. Shared\Models
   跨工作区共用的数据模型。

5. Shared\Services
   公共业务服务。系统 Shell 打开路径统一走 Shell\ShellOpener，不接管 ProcessLauncher。

几条必须知道的约定：

1. 数据只走 ApplicationController
   页面不直接写 JSON；所有读写经过总控制器，再由 Shared\Infrastructure 落盘。
   唯一例外：图标位置保存的撤销按字节回滚 布局档案.xml（DesktopLayout\UI\Pages\DesktopLayoutUndo.cs）。

2. partial 分部
   MainWindow 和 ApplicationController 都拆在多个文件里，改之前先全局搜索全部 partial class。

3. 页面文件命名
   StartupWorkspacePage 目录里的分部文件都带 StartupWorkspacePage. 前缀；BrowserPageBindingDialog.cs 是页面专属独立对话框，不带前缀。

4. 拖动
   视觉零件在 Shared\UI\Cards\Drag，几何计算在 Shared\Core\Cards\Drag；三个工作区共用同一个 DragMoveSession。
   起手手势（前缀组合键 + 左键/右键）只在 Shared\UI\Cards\Drag\Gesture 定义；≡ 手柄固定左键直接拖。

5. 卡片按钮
   顺序/尺寸/间距只在 Shared\UI\Cards\Actions 定义；页面只绑 Click 和拖动，不再自己写按钮尺寸或空位。

6. 颜色与文案
   颜色只从 Shared\UI\Theme\Tokens 和 ThemeResourceKeys 取；用户可见文案只从
   Shared\UI\Text\Localization 的当前语言资源取；恢复完成句子只从 Shared\UI\Text\Restore 取。
   主题切换立即生效；语言切换也立即生效，不重启程序。
   AppText 用不可变快照替换 + LanguageChanged；LocalizedText 更新已创建控件的文字，
   HelpHint / AccessibleToolTip 重新解析提示定义，设置页导航按 key 重建。

7. 多语言目录
   按语言分类的只有 Shared\UI\Text\Localization\Resources\{语言代码}\；
   不建 ChineseText.cs / EnglishText.cs，也不按语言复制页面。
   语言目录名用 BCP 47（zh-CN / en-US / ja-JP），显示名放 _language.json。
   语言目录内按功能分：{功能}/{功能}.json（Common、Settings、Shell、StartupRestore、
   Applications、DesktopLayout、RecycleBin）；一个功能一个文件，页面/提示/消息不再拆开。
   新增语言只加目录和 JSON，不改 C#；未完成语言 uiReady=false，不显示。
   用户切换语言时 AppText 换快照并触发 LanguageChanged，已创建界面即时更新。

8. 单实例
   程序只允许一个实例，构建或跑探针前先退出旧实例。

9. Shell 打开路径只走 ShellOpener
   页面里的“打开文件/文件夹/桌面项目/截图”统一调用 Shared\Services\Shell\ShellOpener；
   不要在页面里直接写 Process.Start。恢复项目、浏览器窗口仍走 ProcessLauncher，不要混在一起。

   为什么 ShellOpener 放在 Services\Shell，而不是 Core 或 UI：
   因为它既不是“数据和算法”，也不是 WPF 界面。它只做 UseShellExecute 这一个系统动作，
   测试模式返回 Suppressed，不真的启动进程。

   注意：Shared\UI\Shell 是应用外壳（App、MainWindow、ApplicationController），
   和 Shared\Services\Shell（操作系统 Shell 打开路径）不是同一件事。

10. 方案镜像分两层
   纯命名、重名顺延、相对目录段在 Shared\Core\Cards\PlanFolders\Mirror；
   建目录、写 启动清单.txt / 方案.json、删旧目录、按文件夹删方案的安全网在
   Shared\Infrastructure\PlanMirrors；两个公开壳在 WorkspaceRestorer.Infrastructure 命名空间下，
   只保留各自的中文清单文字。

   为什么 PlanFolderMirrorEngine 放在 Infrastructure\PlanMirrors，而不是 Core 或 UI：
   因为它既不是“数据和算法”，也不是 WPF 界面。它要读 AppPaths、建目录、写文件、删目录、记日志，
   放 Core 会把磁盘副作用混进纯规则，放 UI 会让控制器和测试反向依赖界面。

   两个公开类不能合并成一个业务类：工作方案和自启动方案仍是两套数据、两套清单文字。

10. 浏览器代码分两层
   浏览器能力/行为（采集、恢复、校验、任务栏身份、跳转导航与目标窗口选择）只放
   StartupRestore\Browsers。产品差异主要在 SharedBrowser\Definitions\BrowserCatalog；
   Edge 的专属定义与配置在 MicrosoftEdge，公共引擎放 SharedBrowser。
   浏览器方案数据规则（标签顺序、窗口/标签身份修复）被 Shared UI 和自启动应用直接调用，
   放 Shared\Core\BrowserPlan，不塞回某个工作区。
   UI/Core 不再新增浏览器标题解析、标签身份或跳转选择；界面只留点击接线、候选收集、状态栏和选择框，
   目标窗口怎么选由 Browsers\SharedBrowser\Jump\BrowserJumpWindowIdentity 统一决定。
   自启动应用只通过适配层、控制器和主窗口入口借用，不复制浏览器逻辑。
   加新浏览器一般只改 BrowserCatalog；需要专属配置时再建产品目录，不改采集/恢复/跳转主流程。

11. 编辑页拖拽边界只有一份
   图标位置编辑页里所有自由拖拽物体（新图标标签、画布图标浮卡、新图标卡片浮卡）的移动边界
   统一走 DesktopLayout\UI\Editor\EditorDragBounds.cs。标签/卡片传编辑页矩形，画布图标传
   可见预桌面矩形；界面只传边界和物体尺寸，不要另写夹取。边界只夹移动、不结束拖动；
   鼠标在界外、物体仍在边界内/贴边，拖动继续；回界内当帧 1:1 接住，不再做 48 DIP 追赶。
   拖动开始缓存边界/页面原点/轴心，页内用 Mouse.GetPosition，出窗口才 GetCursorPos；
   MouseMove 与 16ms 定时器只请求合并更新，标签尺寸不在拖动中重复写。
   松手后的落点仍各走各的：tile 吸附网格、卡片放最近格、标签记住位置。

12. 固定目录名与文件夹收编分三层
   两套目录名（英文/中文）在 variants\*.json，构建时生成 DataLayout.g.cs，
   AppPaths 只引用生成常量，业务代码不写目录名字符串。
   启动时先在 Shared\Infrastructure\DataFolderMigration 把数据目录统一成当前这套名字（两套互认），
   再在 Shared\Infrastructure\PlanMirrors\MirrorIntake 把未登记的方案文件夹交给三选一：
   导入 / 暂不导入 / 移到“无法识别”；读不出来的仍只搬到“无法识别”；
   界面弹框在 Shared\UI\Shell\MirrorIntakeDialog.cs，编排在 ApplicationController.MirrorIntake。
